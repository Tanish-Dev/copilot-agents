Quick Start

You have two easy ways to install agents. Both options end in the same result: all agent files available inside .github/agents/ for Copilot.

Option A: One Command (Fastest)

Run this in your project root and it creates .github/agents/ and copies all agent files automatically.

Mac / Linux

curl -fsSL https://raw.githubusercontent.com/Tanish-Dev/copilot-agents/main/install-global.sh | bash -s -- --project .

Windows (PowerShell)

New-Item -Path .github\agents -ItemType Directory -Force; Invoke-RestMethod https://api.github.com/repos/Tanish-Dev/copilot-agents/contents/agents | Where-Object {$_.name -match '\.agent\.md$'} | ForEach-Object { Invoke-WebRequest $_.download_url -OutFile ".github\agents\$($_.name)" }
1

Paste and run the command in your repo root.

2

Verify you now have .github/agents/*.agent.md.

3

Commit and push the agent files to your default branch.

Option B: Manual Folder + File Copy

Use this path if you prefer explicit control over where files are copied. 

mkdir -p .github/agents
cp /path/to/copilot-agents/agents/*.agent.md .github/agents/
1

Create the folder exactly as .github/agents.

2

Copy all *.agent.md files from this repo’s agents/ folder.

3

Commit and push .github/agents/*.agent.md to your default branch.

After either option: open Copilot Chat or Copilot CLI, choose any of these agents, and run with your preferred supported Copilot model.

Optional: VS Code UI Setup

1

Open Copilot Chat → agent dropdown → Configure Custom Agents…

2

Choose Workspace, then create files inside .github/agents/.

3

Paste agent content and save. Agents appear in the picker immediately.

Agent File Format

File Anatomy

---
name: My Agent
description: What I do and trigger keywords
tools: ['read', 'edit', 'search', 'run_command']
model: claude-sonnet-4-5  # optional
---

# System prompt (up to 30,000 chars)
# Define: persona, rules, output format, examples

Tool Reference

read       ← always include
edit       ← agent modifies files
create     ← agent creates new files
search     ← agent searches/greps
run_command ← runs shell commands
fetch      ← reads URLs/external docs

Efficiency Tips

Context Loading

  • Use @workspace before complex tasks so the agent sees your full repo structure
  • Name files explicitly: "review src/api/auth.py" not "review my auth code"
  • Chain agents: System Designer first → Full Stack Dev to implement

Trigger Keywords

  • Add trigger words in the description (like "secaudit") — Copilot auto-routes
  • CLI flag: --agent=security-auditor forces a specific agent
  • Handoffs: VS Code's handoff feature chains agents in one session

Model Selection

  • Use claude-sonnet for code-heavy tasks (AI Engineer, Full Stack Dev)
  • Use GPT-4.1 for fast, routine tasks like writing docstrings
  • Use Claude Opus for proposals and system design — bigger context window

Global vs Workspace

  • User profile (global): Code Reviewer, Doc Writer, Security Auditor
  • Workspace (repo-specific): AI Engineer, Full Stack Dev, ML Researcher
  • Global agents are available across every VS Code project

Agent Handoffs

  • Use "continue with @full-stack-dev" to hand off context between agents
  • Reference the previous agent's output: "take the architecture @system-designer created and..."
  • Keep one agent per task — don't mix concerns in a single session

MCP Supercharger

  • Connect GitHub MCP to let agents read issues, PRs, and repo data natively
  • Add Figma MCP to Full Stack Dev for design-to-code directly
  • Add your local docs MCP so agents know your team's conventions
