Quick Start

⎈ VS Code Setup

1

Open Copilot Chat → click the agents dropdown → Configure Custom Agents…

2

Choose Workspace (repo-specific) or User Profile (global across all projects)

3

Name the file → VS Code creates .github/agents/agent-name.agent.md

4

Paste the agent config below → save → agent appears in dropdown instantly

⚡ CLI & GitHub.com

1

Copy files from agents/ into .github/agents/ in your project

2

Commit and push to your default branch

3

CLI: copilot --agent=ai-engineer --prompt "your task"

4

GitHub.com: go to github.com/copilot/agents → pick repo → select agent

Agent File Format

File Anatomy

---
name: My Agent
description: What I do and trigger keywords
tools: ['read', 'edit', 'search', 'run_command']
model: claude-sonnet-4-5  # optional
---

# System prompt (up to 30,000 chars)
# Define: persona, rules, output format, examples

Tool Reference

read       ← always include
edit       ← agent modifies files
create     ← agent creates new files
search     ← agent searches/greps
run_command ← runs shell commands
fetch      ← reads URLs/external docs

Efficiency Tips

⚡ Context Loading

  • Use @workspace before complex tasks so the agent sees your full repo structure
  • Name files explicitly: "review src/api/auth.py" not "review my auth code"
  • Chain agents: System Designer first → Full Stack Dev to implement

🎯 Trigger Keywords

  • Add trigger words in the description (like "secaudit") — Copilot auto-routes
  • CLI flag: --agent=security-auditor forces a specific agent
  • Handoffs: VS Code's handoff feature chains agents in one session

🧠 Model Selection

  • Use claude-sonnet for code-heavy tasks (AI Engineer, Full Stack Dev)
  • Use GPT-4.1 for fast, routine tasks like writing docstrings
  • Use Claude Opus for proposals and system design — bigger context window

📦 Global vs Workspace

  • User profile (global): Code Reviewer, Doc Writer, Security Auditor
  • Workspace (repo-specific): AI Engineer, Full Stack Dev, ML Researcher
  • Global agents are available across every VS Code project

🔄 Agent Handoffs

  • Use "continue with @full-stack-dev" to hand off context between agents
  • Reference the previous agent's output: "take the architecture @system-designer created and..."
  • Keep one agent per task — don't mix concerns in a single session

🛠 MCP Supercharger

  • Connect GitHub MCP to let agents read issues, PRs, and repo data natively
  • Add Figma MCP to Full Stack Dev for design-to-code directly
  • Add your local docs MCP so agents know your team's conventions
